Privacy policy

How B2L handles local choices, Android SDK registration, Expo updates, optional Microsoft reports, sharing, support and website requests.

Effective / มีผลตั้งแต่ 2026-10-24 · iOS and Android

These pages cover bundled teaching content, automatic Expo update processing in update-enabled builds, and optional Microsoft report features where available in your installed version. หน้าเหล่านี้ครอบคลุมเนื้อหาฝึกอ่านข้อมูลที่มากับแอป การประมวลผลอัปเดต Expo อัตโนมัติในรุ่นที่เปิดใช้ และฟังก์ชันรายงาน Microsoft ที่เลือกเปิดได้ในรุ่นที่คุณติดตั้ง

Privacy policy

This policy covers Borrow to Learn (B2L), the iOS and Android teaching app identified as com.tanatt.borrowtolearn, and these B2L information pages. The App Store developer is Tanat Tonguthaisri; the Google Play developer display name is Harness Engineer. For privacy and support requests, contact la@defense.engineer.

What B2L is: an educational data explorer for learners aged 13 and above. All counts, amounts, ratios and reporting periods in B2L's bundled teaching examples are invented. Province names are geographic labels. The optional external DIGI report and SharePoint submission package have their own content, sources and permissions; their figures are separate from the fictional B2L teaching dataset. B2L's teaching tools do not provide loans, payments, personal account balances or eligibility decisions. B2L does not ask you to upload financial records.

1. Learning choices stored by the app

The app stores your saved story identifiers, language, appearance choice and teaching-profile identifier in app-local storage so you can return to the same reading experience. Search text, filters and comparisons are handled as app state; B2L has no service receiving a history of those interactions. There is no B2L user account, cloud bookmark sync or app-operated account database. Optional Microsoft sign-in is separate, as explained in section 4.

Local storage is distinct from operating-system backups and device transfer. Your device or backup provider may preserve app data according to your settings. The current Android build disables its standard app-backup flag; this is not a guarantee that no external copy can exist.

2. Android notification infrastructure

The Android version includes Google Firebase Cloud Messaging and Firebase Installations. These native components can register automatically, processing per-installation identifiers, messaging registration/configuration and basic app, SDK and device metadata. Network services also receive request information such as the IP address. This supports the included registration infrastructure; B2L version 1.0 does not expose a notification-subscription or token-management feature.

Not allowing notification display does not itself disable that registration processing. See Firebase's Android data disclosure and automatic registration documentation.

3. iOS and other app services

The iOS version uses Apple's notification capability but does not request an APNs push token through B2L's application code. The reviewed iOS release does not include the Android Firebase components described above. B2L's bundled teaching tools have no advertising, advertising-ID integration, in-app behavioural analytics or automatic upload of your teaching interactions. Earlier reviewed builds had Expo over-the-air updates disabled. Update-enabled builds use the separate service described below.

B2L's bundled teaching tools do not send your content to a cloud AI service. Features available on an external Microsoft page, including any Copilot availability, depend on Microsoft and the report owner's settings and terms. B2L does not guarantee those external features.

Apple, Google and your operating system may process store, purchase/download, security or optional diagnostic information under their own settings and policies. Those platform services are separate from B2L's app-operated functions.

3a. Expo EAS Update on both platforms

In versions of B2L with Expo EAS Update enabled, the app automatically checks Expo's update service at startup and can download compatible application code and assets. Requests include a random client identifier saved on the device, platform/runtime information and update identifiers, including failed-update information when relevant. A limited summary of an earlier fatal error can also be sent for error recovery. The service receives ordinary connection information such as an IP address. This processing supports update delivery and recovery and does not require a B2L or Microsoft account.

Bundled teaching content remains available offline. When a connection is available, automatic update requests can occur without opening an external report. Expo's handling is described in its privacy policy. Optional Microsoft services and Android Firebase infrastructure have the separate processing described in this policy.

4. Exports, sharing and external links

When you export a table, B2L creates a CSV file in its app cache and offers the device share interface. The cache file is not immediately deleted by the app; system cache cleanup or removal of app data can remove it. If you save, email or share a copy, the destination you choose receives it. Shared files and story text contain the selected teaching content and its context, rather than a real borrower account.

The bundled B2L learning journey, charts, comparisons and saved stories work without a B2L account or Microsoft sign-in. If you choose to open the external report, submission package or web journey, your browser connects to that service. The report requires internet access and an authorized Microsoft account. The SharePoint package needs internet access and can require separate Microsoft sign-in and permissions; access to one does not guarantee access to the other. Sign-in happens on Microsoft's pages. B2L's report-link feature does not collect your Microsoft password or send your saved-story list or preferences as part of the link.

Microsoft and, where applicable, your organization may process connection, account and usage information under their policies. Review the Microsoft Privacy Statement and your organization's rules before using a work or school account.

Support email and sharing remain optional. Your email application or sharing destination receives the information you choose to send under its own policies.

5. Support messages

If you email us, we receive your sender address, message and any attachments you choose to include. We use this information to reply, troubleshoot the issue, handle privacy requests and protect the service. Email providers process message delivery and storage. Do not send passwords, API keys, government-ID images, bank details or private financial records.

6. Recipients, purposes and security

The data flows above serve the feature you choose, SDK registration, update delivery/recovery, support, website delivery or security. Relevant recipients are Google/Firebase for Android infrastructure, Expo for update-enabled builds on both platforms, Microsoft and the relevant organization for optional report and SharePoint use, Apple/Google and your device or backup provider for platform services, email providers for support, hosting/security providers for these webpages, and any sharing destination you choose. B2L does not sell personal information or use it for targeted advertising. Information may also be retained or disclosed where a valid legal obligation requires it.

HTTPS is used for these webpages and supported provider connections. Local device security, email security and recipient practices also matter. No online or device-storage system can promise absolute security.

7. These webpages

These B2L information and policy HTML pages contain no B2L analytics script, sign-in form or application cookie. The hosting provider may insert an analytics beacon, but this page's restrictive content-security policy blocks client-side JavaScript; the text and contact links remain usable without it. They are hosted through GitHub Pages and the domain's Cloudflare delivery/security service. These providers receive technical request data such as IP address, browser information, requested URL and time, and may apply their own delivery or security mechanisms. Their processing is explained in the GitHub privacy statement and Cloudflare privacy policy.

8. Retention and deletion

  • Local preferences: kept until you change/remove them or remove app data. Removing one bookmark does not reset all preferences.
  • Export files: app-cache copies can remain until cleanup; copies saved elsewhere remain under that destination's control.
  • Support: retained only as long as needed to handle the request, maintain necessary support/security records and meet applicable legal obligations; removed when no longer needed.
  • Firebase identifiers: controlled by the provider's lifecycle and deletion process. Google's privacy page describes removal from live and backup systems within 180 days after a Firebase customer requests deletion through the relevant API. Uninstalling is not confirmation that such an API request occurred.
  • Expo EAS Update in update-enabled builds: The update client identifier is stored in device preferences and reused on later launches. Clearing local B2L data does not request deletion of records already held by Expo. Contact la@defense.engineer about identifiable update-service data; handling depends on the record and provider process. No fixed provider deletion period or removal from every backup is promised. The app has no EAS-client-ID display or provider-record deletion control.
  • External Microsoft/browser data: External Microsoft/browser data follows the relevant provider and organization retention rules. Removing B2L app data does not request deletion of a Microsoft account, SharePoint file or provider access record, or guarantee that a browser session is cleared. Use the provider's privacy controls or contact your organization administrator for those requests.
  • Website/platform logs and backups: follow the relevant provider's retention rules.

See Data deletion instructions and Firebase privacy and retention. B2L version 1.0 has no Firebase-ID display or remote-ID deletion button. Deleting an old provider record does not disable future registration: an active or reinstalled SDK can create a new installation identifier.

9. Your choices and rights

You can change language/appearance, remove saved stories, avoid optional sharing, clear local app data, manage device backups and contact us about support-message or other identifiable data. Depending on applicable law, you may have rights of access, correction, deletion, restriction, objection or portability, and withdrawal of consent where processing relies on consent. You may also contact your local data-protection authority. Explain your request by email; we will ask only for information reasonably needed to identify and handle it.

Local settings and support actions are processed to provide the functions you request. Provider-side processing is governed by the applicable service terms and privacy rules. If you need information about the basis or recipient for a particular data flow, contact us. A device permission is not a blanket consent to every processing activity.

10. Teen users

B2L is intended for ages 13–15, ages 16–17 and adults; it is not designed for children under 13. It does not ask for a birth date or automatically verify age. The SDK processing described above can occur for an installed copy. If a child has sent personal information in a support message, a parent or guardian can contact us to request its removal. Where local law requires parental involvement or a different age threshold, those requirements continue to apply.

11. International processing and changes

Providers such as Google/Firebase, Expo for update-enabled builds, Microsoft, the relevant account organization, GitHub, Cloudflare and email services may process data in countries other than yours under their applicable safeguards and policies. We will update this page and the relevant store disclosures when B2L's practices change. The effective date above identifies this version of the policy.

Privacy contact: la@defense.engineer.

นโยบายความเป็นส่วนตัว

นโยบายนี้ครอบคลุมแอป Borrow to Learn (B2L) บน iOS และ Android รหัส com.tanatt.borrowtolearn และหน้าเว็บข้อมูล B2L ผู้พัฒนาที่แสดงบน App Store คือ Tanat Tonguthaisri และชื่อผู้พัฒนาที่แสดงบน Google Play คือ Harness Engineer ติดต่อเรื่องความเป็นส่วนตัวและความช่วยเหลือได้ที่ la@defense.engineer

B2L เป็นแอปเพื่อเรียนรู้ข้อมูลสำหรับอายุ 13 ปีขึ้นไป จำนวน เงิน อัตราส่วน และช่วงรายงานในตัวอย่างที่มากับแอป B2L สมมติขึ้นเพื่อการเรียนรู้ ชื่อจังหวัดเป็นป้ายพื้นที่ ส่วนรายงาน DIGI และชุดงานส่งใน SharePoint ที่เลือกเปิดภายนอกมีเนื้อหา แหล่งข้อมูล และสิทธิ์ของตนเอง ตัวเลขเหล่านั้นแยกจากชุดข้อมูลสมมติ B2L เครื่องมือฝึกอ่านข้อมูล B2L ไม่ให้กู้ ไม่รับชำระ ไม่แสดงยอดบัญชีส่วนบุคคล และไม่ตัดสินสิทธิ B2L ไม่ขอให้อัปโหลดเอกสารการเงินส่วนบุคคล

1. สิ่งที่แอปเก็บไว้เพื่อการอ่าน

แอปเก็บรหัสเรื่องที่บันทึก ภาษา รูปแบบการแสดงผล และรหัสชุดข้อมูลเพื่อการเรียนรู้ไว้ในพื้นที่ข้อมูลของแอป คำค้น ตัวกรอง และการเปรียบเทียบเป็นสถานะการใช้งาน โดยไม่มีบริการ B2L ที่รับประวัติการทำรายการเหล่านี้ ไม่มีบัญชีผู้ใช้ B2L หรือการซิงก์เรื่องที่บันทึกไปยังฐานข้อมูลบัญชีของ B2L ส่วนการลงชื่อเข้าใช้ Microsoft ภายนอกเป็นทางเลือกที่อธิบายในหัวข้อ 4

ข้อมูลในแอปต่างจากข้อมูลสำรองและการย้ายเครื่อง ระบบปฏิบัติการหรือผู้ให้บริการสำรองข้อมูลอาจเก็บสำเนาตามการตั้งค่าของคุณ Android รุ่นปัจจุบันปิดแฟล็กสำรองข้อมูลมาตรฐานของแอป แต่ไม่ได้รับรองว่าจะไม่มีสำเนาภายนอกทุกประเภท

2. โครงสร้างพื้นฐาน Firebase บน Android

รุ่น Android มี Google Firebase Cloud Messaging และ Firebase Installations ซึ่งอาจลงทะเบียนโดยอัตโนมัติผ่านส่วน native โดยประมวลผลรหัสการติดตั้ง การลงทะเบียนและการตั้งค่าระบบข้อความ ตลอดจนข้อมูลเทคนิคทั่วไปของแอป SDK และอุปกรณ์ บริการเครือข่ายได้รับข้อมูลคำขอ เช่น IP address ด้วย รุ่น 1.0 ไม่มีหน้าสมัครรับการแจ้งเตือนหรือจัดการโทเคนให้ผู้ใช้

การไม่อนุญาตให้แสดงการแจ้งเตือนไม่ได้ยืนยันว่าหยุดการลงทะเบียนนี้แล้ว อ่านรายละเอียดจาก ข้อมูลที่ Firebase เปิดเผยสำหรับ Android และ การเริ่มลงทะเบียนอัตโนมัติ

3. iOS และบริการแพลตฟอร์ม

รุ่น iOS มี capability สำหรับการแจ้งเตือนของ Apple แต่โค้ดแอป B2L ไม่ได้ร้องขอ APNs push token และรุ่น iOS ที่ตรวจไม่พบส่วน Firebase แบบ Android ข้างต้น เครื่องมือฝึกอ่านข้อมูลที่มากับ B2L ไม่มีโฆษณา การใช้ Advertising ID ระบบวิเคราะห์พฤติกรรมในแอป หรือการอัปโหลดกิจกรรมการเรียนรู้อัตโนมัติ รุ่นก่อนที่ตรวจปิด Expo OTA update ไว้ ส่วนรุ่นที่เปิดใช้อัปเดตใช้บริการแยกตามหัวข้อด้านล่าง

เครื่องมือฝึกอ่านข้อมูลที่มากับ B2L ไม่ส่งเนื้อหาของคุณไปยังบริการ AI บนคลาวด์ ฟังก์ชันในหน้า Microsoft ภายนอก รวมถึงการมี Copilot ให้ใช้ ขึ้นกับการตั้งค่าและเงื่อนไขของ Microsoft กับเจ้าของรายงาน B2L ไม่รับรองว่าฟังก์ชันภายนอกเหล่านั้นจะใช้งานได้

Apple Google และระบบปฏิบัติการอาจประมวลผลข้อมูลร้านค้า การดาวน์โหลด ความปลอดภัย หรือข้อมูลวินิจฉัยที่เลือกเปิดไว้ตามนโยบายของตน ซึ่งแยกจากฟังก์ชันที่ B2L ดำเนินการ

3ก. Expo EAS Update บนทั้งสองแพลตฟอร์ม

ในรุ่น B2L ที่เปิดใช้ Expo EAS Update แอปจะตรวจบริการอัปเดตของ Expo โดยอัตโนมัติเมื่อเริ่มทำงาน และอาจดาวน์โหลดโค้ดกับไฟล์ประกอบที่เข้ากันได้ คำขอมีรหัสไคลเอนต์แบบสุ่มที่เก็บไว้ในอุปกรณ์ ข้อมูลแพลตฟอร์มและรุ่นที่ใช้จับคู่ความเข้ากันได้ ตลอดจนรหัสอัปเดต รวมถึงข้อมูลอัปเดตที่เริ่มทำงานไม่สำเร็จเมื่อเกี่ยวข้อง ระบบอาจส่งสรุปข้อผิดพลาดร้ายแรงก่อนหน้าที่จำกัดความยาวเพื่อช่วยกู้คืนการทำงาน ผู้ให้บริการยังได้รับข้อมูลการเชื่อมต่อทั่วไป เช่น IP address การประมวลผลนี้ใช้เพื่อส่งอัปเดตและกู้คืนการทำงาน โดยไม่ต้องมีบัญชี B2L หรือ Microsoft

เนื้อหาฝึกอ่านข้อมูลที่มากับแอปยังอ่านได้ออฟไลน์ เมื่อเชื่อมต่อเครือข่าย คำขออัปเดตอัตโนมัติอาจเกิดขึ้นได้โดยไม่ต้องเปิดรายงานภายนอก การจัดการข้อมูลของ Expo อธิบายในนโยบายความเป็นส่วนตัว ส่วนบริการ Microsoft ที่เลือกเปิดและโครงสร้างพื้นฐาน Firebase บน Android มีการประมวลผลแยกตามที่ระบุในนโยบายนี้

4. ไฟล์ส่งออก การแชร์ และลิงก์

เมื่อส่งออกตาราง แอปสร้าง CSV ในแคชและเปิดช่องทางแชร์ของอุปกรณ์ ไฟล์แคชไม่ได้ถูกลบทันทีโดยแอป แต่อาจถูกลบเมื่อระบบล้างแคชหรือลบข้อมูลแอป หากคุณบันทึกหรือส่งสำเนาไปยังแอป อีเมล หรือบริการอื่น ปลายทางนั้นจะได้รับสำเนาที่คุณเลือก เนื้อหาคือข้อมูลตัวอย่างและบริบท ไม่ใช่บัญชีผู้กู้จริง

เส้นทางเรียนรู้ กราฟ การเปรียบเทียบ และเรื่องที่บันทึกจากเนื้อหาที่มากับ B2L ใช้ได้โดยไม่ต้องมีบัญชี B2L หรือลงชื่อเข้าใช้ Microsoft เมื่อเลือกเปิดรายงาน ชุดงานส่ง หรือเส้นทางบนเว็บ เบราว์เซอร์จะเชื่อมต่อไปยังบริการนั้น รายงานต้องใช้อินเทอร์เน็ตและบัญชี Microsoft ที่มีสิทธิ์ ส่วนชุดงานส่งใน SharePoint ต้องใช้อินเทอร์เน็ตและอาจต้องลงชื่อเข้าใช้ Microsoft พร้อมสิทธิ์แยกต่างหาก สิทธิ์เปิดรายการหนึ่งไม่ได้รับรองสิทธิ์เปิดอีกรายการ การลงชื่อเข้าใช้เกิดบนหน้าของ Microsoft ฟังก์ชันลิงก์รายงานของ B2L ไม่เก็บรหัสผ่าน Microsoft หรือแนบรายการเรื่องที่บันทึกและการตั้งค่าไปกับลิงก์

Microsoft และองค์กรของคุณในกรณีที่เกี่ยวข้องอาจประมวลผลข้อมูลการเชื่อมต่อ บัญชี และการใช้งานตามนโยบายของตน ก่อนใช้บัญชีที่ทำงานหรือสถานศึกษา โปรดอ่านนโยบายความเป็นส่วนตัวของ Microsoft และข้อกำหนดขององค์กร

การส่งอีเมลช่วยเหลือและการแชร์ยังเป็นทางเลือก แอปอีเมลหรือปลายทางแชร์ได้รับข้อมูลที่คุณเลือกส่งตามนโยบายของตน

5. ข้อความขอความช่วยเหลือ

หากคุณส่งอีเมล เราได้รับอีเมลผู้ส่ง ข้อความ และไฟล์ที่คุณเลือกแนบ ใช้เพื่อตอบ แก้ปัญหา จัดการคำขอด้านข้อมูล และดูแลความปลอดภัย ผู้ให้บริการอีเมลมีส่วนในการรับส่งและจัดเก็บ อย่าส่งรหัสผ่าน API key ภาพบัตรประจำตัว ข้อมูลธนาคาร หรือเอกสารการเงินส่วนบุคคล

6. ผู้รับข้อมูล วัตถุประสงค์ และความปลอดภัย

การประมวลผลข้างต้นใช้เพื่อฟังก์ชันที่คุณเลือก การลงทะเบียน SDK การส่งอัปเดตและกู้คืนการทำงาน ความช่วยเหลือ การให้บริการเว็บ และความปลอดภัย ผู้เกี่ยวข้องได้แก่ Google/Firebase สำหรับ Android Expo สำหรับรุ่นที่เปิดใช้อัปเดตบนทั้งสองแพลตฟอร์ม Microsoft และองค์กรที่เกี่ยวข้องสำหรับรายงานและ SharePoint ที่เลือกใช้ ผู้ให้บริการแพลตฟอร์ม อุปกรณ์และข้อมูลสำรอง ผู้ให้บริการอีเมล ผู้ให้บริการเว็บ/ความปลอดภัย และปลายทางแชร์ที่คุณเลือก B2L ไม่ขายข้อมูลส่วนบุคคลหรือใช้เพื่อโฆษณาเจาะจงบุคคล อาจเก็บหรือเปิดเผยข้อมูลเมื่อมีหน้าที่ตามกฎหมายที่ใช้บังคับ

หน้าเว็บนี้และการเชื่อมต่อผู้ให้บริการที่รองรับใช้ HTTPS ความปลอดภัยของเครื่อง อีเมล และปลายทางที่คุณเลือกมีส่วนสำคัญ ไม่มีระบบใดรับรองความปลอดภัยได้อย่างสมบูรณ์

7. หน้าเว็บเหล่านี้

ไฟล์ HTML ในชุดหน้าเว็บข้อมูลและนโยบาย B2L นี้ไม่มีสคริปต์วิเคราะห์ของ B2L แบบฟอร์มเข้าสู่ระบบ หรือคุกกี้แอป ผู้ให้บริการโฮสต์อาจเพิ่ม beacon วิเคราะห์ แต่ Content Security Policy ของหน้านี้บล็อก JavaScript ฝั่งผู้ใช้ เนื้อหาและลิงก์ติดต่ออ่านได้โดยไม่ต้องใช้สคริปต์ ให้บริการผ่าน GitHub Pages และระบบส่งเนื้อหา/ความปลอดภัยของโดเมนโดย Cloudflare ผู้ให้บริการได้รับข้อมูลคำขอ เช่น IP เบราว์เซอร์ URL และเวลา และอาจใช้กลไกส่งเนื้อหาหรือความปลอดภัยของตน อ่าน นโยบาย GitHub และ นโยบาย Cloudflare

8. ระยะเวลาเก็บและการลบ

  • การตั้งค่าและเรื่องที่บันทึกอยู่จนกว่าจะเปลี่ยน ลบรายการ หรือลบข้อมูลแอป การลบบุ๊กมาร์กหนึ่งรายการไม่ใช่การล้างทุกการตั้งค่า
  • ไฟล์แคชอาจอยู่จนกว่าระบบจะล้าง ส่วนสำเนาภายนอกอยู่ภายใต้ปลายทางนั้น
  • อีเมลช่วยเหลือเก็บเท่าที่จำเป็นต่อคำขอ ประวัติความช่วยเหลือ/ความปลอดภัยที่จำเป็น และหน้าที่ตามกฎหมาย แล้วลบเมื่อไม่มีความจำเป็น
  • รหัส Firebase มีวงจรเก็บและลบแยกต่างหาก Google อธิบายการลบจากระบบใช้งานและสำรองภายใน 180 วันหลังลูกค้า Firebase ส่งคำขอลบผ่าน API ที่เกี่ยวข้อง การถอนแอปไม่ได้ยืนยันว่าได้เรียก API ดังกล่าว
  • Expo EAS Update ในรุ่นที่เปิดใช้อัปเดต: รหัสไคลเอนต์สำหรับอัปเดตเก็บในข้อมูลการตั้งค่าของอุปกรณ์และนำกลับมาใช้เมื่อเปิดแอปครั้งต่อไป การล้างข้อมูล B2L ในเครื่องไม่ได้ส่งคำขอลบรายการที่ Expo เก็บไว้แล้ว หากต้องการสอบถามข้อมูลบริการอัปเดตที่ระบุได้ ให้ติดต่อ la@defense.engineer การดำเนินการขึ้นกับรายการและขั้นตอนของผู้ให้บริการ โดยไม่รับรองกำหนดเวลาลบตายตัวหรือการลบข้อมูลสำรองทุกชุด แอปไม่มีหน้าดูรหัสไคลเอนต์ EAS หรือปุ่มลบรายการของผู้ให้บริการ
  • ข้อมูลในบริการ Microsoft และเบราว์เซอร์ภายนอกเป็นไปตามกฎการเก็บข้อมูลของผู้ให้บริการและองค์กรที่เกี่ยวข้อง การลบข้อมูลแอป B2L ไม่ได้ส่งคำขอลบบัญชี Microsoft ไฟล์ SharePoint หรือบันทึกการเข้าถึงของผู้ให้บริการ และไม่รับรองว่าจะล้างเซสชันเบราว์เซอร์ ให้ใช้เครื่องมือความเป็นส่วนตัวของบริการหรือติดต่อผู้ดูแลระบบขององค์กรสำหรับคำขอเหล่านั้น
  • บันทึกเว็บ แพลตฟอร์ม และข้อมูลสำรองเป็นไปตามกฎของผู้ให้บริการนั้น

ดู วิธีลบข้อมูล และ การเก็บข้อมูลของ Firebase รุ่น 1.0 ไม่มีปุ่มแสดงรหัส Firebase หรือลบรหัสจากเซิร์ฟเวอร์ การลบรหัสเดิมไม่ได้ปิดการลงทะเบียนในอนาคต SDK ที่ยังทำงานหรือติดตั้งใหม่อาจสร้างรหัสการติดตั้งใหม่ได้

9. ทางเลือกและสิทธิของคุณ

คุณเปลี่ยนภาษา/ธีม ลบเรื่องที่บันทึก งดแชร์ ล้างข้อมูลแอป จัดการข้อมูลสำรอง และติดต่อเกี่ยวกับข้อมูลที่ระบุได้ เช่น อีเมลช่วยเหลือได้ สิทธิตามกฎหมายที่ใช้บังคับอาจรวมถึงการเข้าถึง แก้ไข ลบ จำกัด คัดค้าน โอนข้อมูล หรือถอนความยินยอมเมื่อการประมวลผลอาศัยความยินยอม รวมถึงร้องเรียนต่อหน่วยงานคุ้มครองข้อมูลในพื้นที่ เราขอเฉพาะข้อมูลที่จำเป็นอย่างสมเหตุสมผลเพื่อระบุและจัดการคำขอ

การตั้งค่าในเครื่องและการตอบข้อความใช้เพื่อให้บริการที่คุณร้องขอ ส่วนผู้ให้บริการดำเนินการตามข้อตกลงและกฎความเป็นส่วนตัวของตน หากต้องการทราบฐานหรือผู้รับของการประมวลผลใด โปรดติดต่อ การอนุญาตของอุปกรณ์ไม่ใช่ความยินยอมครอบคลุมทุกกิจกรรม

10. ผู้ใช้อายุน้อย

B2L ตั้งใจสำหรับอายุ 13–15 ปี 16–17 ปี และผู้ใหญ่ ไม่ได้ออกแบบสำหรับเด็กอายุต่ำกว่า 13 ปี แอปไม่ขอวันเกิดหรือยืนยันอายุอัตโนมัติ การประมวลผล SDK ตามที่ระบุอาจเกิดขึ้นเมื่อมีการติดตั้ง หากเด็กส่งข้อมูลส่วนบุคคลทางอีเมล ผู้ปกครองติดต่อขอลบได้ ข้อกำหนดผู้ปกครองหรือเกณฑ์อายุที่ต่างกันตามกฎหมายท้องถิ่นยังคงใช้บังคับ

11. การประมวลผลต่างประเทศและการเปลี่ยนแปลง

ผู้ให้บริการ เช่น Google/Firebase Expo ในรุ่นที่เปิดใช้อัปเดต Microsoft องค์กรเจ้าของบัญชี GitHub Cloudflare และอีเมล อาจประมวลผลนอกประเทศของคุณตามมาตรการและนโยบายของตน หากพฤติกรรม B2L เปลี่ยน เราจะปรับหน้านี้และข้อมูลในร้านค้าที่เกี่ยวข้อง วันที่มีผลด้านบนระบุรุ่นของนโยบายนี้
